> 给下一个 agent 的完整交接。**读这份 + [`web-console.md`](web-console.md) + [`../GLOSSARY.md`](../GLOSSARY.md) + [`adr/`](adr/) 就能接手**，不需要原会话的上下文。

## 0. 一句话

把斗地主决策助手的展示页，从"一块带黑框的 3D 桌面"改成一台**横握掌机（Nintendo Switch 造型）**：
中间是**屏幕**（屏幕里是 3D 牌桌），左右是**握把**（真正的物理按键区），
机顶是**记牌器**，机侧是**数据面板**。要"游戏机"的效果，不要"画框"。

## 4. 目标造型：Switch 横握（尺寸有官方依据）

**官方尺寸**（Wikipedia 已核实）：原版 `173 × 102 × 14 mm`，OLED `176 × 102 × 14 mm`，
屏幕 `6.2″ 1280×720（16:9 ≈ 137×77 mm）`，两侧 Joy-Con 各约 `35.5 mm` 宽。

**按机身宽 = 10 个单位归一化**（直接拿去建模）：

| 部位 | 比例（宽=10） |
|---|---|
| 机身 | 宽 `10.00` · 高 `5.90` · 厚 `0.81` |
| 屏幕（含边框） | 宽 `7.92` · 高 `4.46` |
| 左右握把（各） | 宽 `2.05` · 高 `5.90` |

> 没找到现成的三视图（Wikimedia Commons 上没有 Switch 的工程图）。上面这套比例是从官方
> 尺寸推出来的，够用；要更准可以自己再找参考图。**注意：只借造型比例，不要出现任天堂商标。**

**映射**（这是重点 —— 让"游戏机"真的成立）：

```
        ┌──────── 机顶：记牌器（一条窄屏，15 个点数 × 还没现身的张数）────────┐
┌───────┴──────────────────────────────────────────────────────┬──────────┐
│  左握把（物理键区）             中屏（嵌入机身）                右握把       │
│  出牌机会 ①②③…                上家[身份]   下家[身份]          牌盘        │
│  撤销 / 导出                        牌桌 / 上一手               出牌/不要   │
│                                 我[身份]（我的牌面）                        │
└──────────────────────────────────────────────────────────────┴──────────┘
   机侧（不参与 3D）：CRT 面板 —— 粒子云（含说明）/ 逐张概率 / 校准
```

- **中屏**：现在那块"带黑框的桌面"要变成**嵌进机身的屏幕** —— 屏幕有内凹的边框、有自发光感
- **左右握把**：真正的按键区（有厚度的键帽），承载出牌机会切换、牌盘、出牌/不要/撤销
- **机顶**：记牌器（票 #23）
- **机侧**：CRT 数据面板（票 #24）

## 5. 参考：复刻 ThreeUI 的**设计手法**（不是抄素材）

- <https://threeui.com/3d-assets/retro-handheld-assets> —— Retro Gaming 3D Asset（同题材）
- <https://threeui.com/landing-pages/retro-gaming-handheld-landing-page> —— 成品落地页
- <https://threeui.com/three-js/retro-metallic> —— 材质取向

要学的是这四条（也是现在最缺的）：

1. **厚度与倒角**：机身是**分层壳体**（上壳/下壳/内衬各一层），不是一块平板；
   屏幕是**内凹**的，握把比机身**略厚**
2. **光**：主光 + 补光 + 边缘高光，让塑料有转折；**屏幕自发光**（emissive），像真的亮着
3. **影子**：机身**投在地面上**，让人相信它是个实物
4. **材质层次**：外壳哑光、屏幕玻璃微反光、按键高光 —— 三种材质不能是同一个灰

**待你确认的一处**：用户说"用那个键帽"，我理解为上面那种**有厚度、有高光、圆角**的塑料键帽
（而不是现在这种平板按钮）。如果理解偏了，先问用户。

## 8. 硬约束（别踩）

- **ADR-0001**：牌局合法性的唯一裁判是**服务端**；前端唯一能施加的约束是"选牌不超过
  牌池里该点数的剩余张数"
- **ADR-0002**：机身用 3D 渲染，但**要读的数字（张数/已出牌/身份/概率/校准）留在平面 HTML**
  —— 中文点阵字进透视会糊。座位标签现在就是按 3D 投影坐标贴上去的，这个做法保留
- **GLOSSARY 用词**：座位名以**我方**为参照（我/上家/下家）；地主农民是**身份徽章**；
  决策点叫「第 N 次**出牌机会**」，全局手数只作次要信息
- **依赖全部本地化**（GSAP / three.js / 像素字体都在 `web/vendor/`），**断网可开**，不许引 CDN
- `prefers-reduced-motion` 下**关掉所有动效**（推镜与视差都要关）
- 窄屏（≤820px）**保持 3D**，固定正视、面板纵向堆叠 —— **不维护第二套 2D 版式**

## 9. 验收标准（7 条）与上次评估结论

| # | 标准 |
|---|---|
| 1 | **像一台机器**：机身/屏幕/握把/机顶/机侧在视觉上是一件整体，不是"3D 装饰 + 普通网页" |
| 2 | **一眼看懂**：没看过这项目的人，能说出"三个人的牌桌，我在下面，两个对手在上面" |
| 3 | **可读性**：张数、已出牌、身份徽章、出牌机会编号都看得清；**我那一手牌的点数能逐张分辨** |
| 4 | **造型与质感按三视图**（`docs/refs/console-3view/`）：剪影/比例/分件/按键以图为准；**允许**倒角高光、AO、环境光渐变与柔影。信息层（记牌条/座位牌/操作台）仍保持点阵字、硬边框、限色 |
| 5 | **层级清楚**：牌桌是主视觉，数据面板是配角，不抢 |
| 6 | **不糊**：中文与数字清晰；3D 场景里的文字大到认得出点数 |
| 7 | **窄屏不崩**：420px 下仍然是一台机器，没有重叠或裁切 |

**上次独立评估（2026-11-01）：不过关，4/7 FAIL。**

- ❌ 1 像一台机器 —— "flat web page with a detached black 3D trapezoid"
- ✅ 2 一眼看懂
- ❌ 3 可读性 —— 我那一手牌 "smeared，常认不出点数"
- ✅ 4 像素风一致（**此条口径已更新**：见 `docs/web-console.md`「视觉基准」——以三视图为准，允许光照渐变）
- ✅ 5 层级清楚
- ❌ 6 不糊 —— 3D 里的牌面分辨率不够
- ❌ 7 窄屏不崩 —— "420px 下退回成一个普通表单页，机器感全没了"

它给的优先级：**① 窄屏保住机器感 → ② 手牌可读 → ③ 机身穿插成一体**。

## 10. 工作方式（用户明确要求，务必遵守）

1. 改完之后，**派一个独立的 sub-agent 去评估**，**不许作者自评**
2. 评估给出 PASS/FAIL + 证据；不过就按它的优先级继续改，**再派一个新的评估 agent**
3. **只有评估过关，才通知用户**（中间不要打扰）
4. **模型限制（要如实告诉用户）**：这把网关 Key **只放行作者同款模型**；
   `vision`（Doubao-Seed-2.1-Pro-solo）与 `explore`（kimi-k3.1-pro-solo）都会 404。
   所以评估 agent 只能是**同款模型 + fork 上下文**，独立性打折 —— 每次都主动声明这一点

评估 agent 的提示词要点：**只给它作品（截图）+ 上面这 7 条 rubric**，不给它的作者的理由；
要求它**逐条 PASS/FAIL + 证据 + 最差项 + 三条优先修复**，并**明确要求它挑刺、不留情面**。
