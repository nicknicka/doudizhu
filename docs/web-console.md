# 展示页：像素游戏机（设计共识）

把展示页重做成一台**像素游戏机**。术语以 [GLOSSARY.md](../GLOSSARY.md) 为准；两条硬决定见
[ADR-0001](adr/0001-合法性由服务端裁定.md) 与 [ADR-0002](adr/0002-机身用3D-文字面板留2D.md)。

## 版式：一件整体

```
        ┌──────────── 机顶：记牌器 ────────────┐
        │  15 个点数 × 还没现身的张数           │
   ┌────┴───────────────────────────────┬────┴────┐
   │            机身（3D）               │ 机侧     │
   │  上家[身份]          下家[身份]      │ CRT 面板 │
   │   牌背                牌背          │ 粒子云   │
   │           牌桌 / 上一手              │ 逐张概率 │
   │        我[身份] · 我的一手（正面）    │ 校准     │
   └────────────────────────────────────┴─────────┘
        ┌──────────── 机下：操作台 ────────────┐
        │ 出牌机会 ①②③… │ 牌盘 │ 出牌/不要/撤销 │
        └──────────────────────────────────────┘
```

- 机身、机顶记牌器、机侧面板是**一件整体**，不是"一个 3D 装饰 + 一个普通网页"。
- 机身、三位角色、三副牌、牌桌由 three.js 渲染成真 3D；**要读的数字仍是平面 HTML**（ADR-0002）。
- 只有**我的一手**是正面，另两家是牌背 + 张数。

## 视觉基准：以三视图为准

造型与质感的**唯一基准**是用户给的三视图，存在
[`docs/refs/console-3view/`](refs/console-3view/)（正面、背面、侧面 3/4、低角度 3/4、英雄图）。

- **几何以图为准**：单块八角机身、暗色轮廓线、米色侧边带、大倒角、机顶记牌槽、
  四角螺丝、金色铭牌、左右上角肩块、黑键 + 金边、屏框内凹。
- **质感以图为准**：图里的塑料有柔和渐变、台面有明暗过渡、屏幕有辉光。
  所以**允许**倒角高光、AO/接触阴影、环境光（IBL）带来的渐变、轻微柔影。
  ~~早期的「不混进圆角/渐变/柔和阴影」条款作废~~ —— 那条是为防止变成
  "普通网页卡片"，不是为了禁用光照；质感正是从这些光照响应里来的。
- **仍然成立**：点阵字、硬边框、限色、像素风的**信息层**（记牌条、座位牌、
  操作台）不许出现渐变色块、圆角卡片和投影式阴影。

一句话：**机器本身要像三视图那样有光和材质；文字与数据仍然保持像素化平面风格。**

## 壳子：两条路，一个开关

机身有**两个来源**，用 URL 上的开关选，默认不变（不加参数就是代码建模）：

| 开关 | 机身 | 材质/光照 |
|---|---|---|
| （默认） | `web/app/scene.js` 里代码建模 | 平涂 + 硬描边 |
| `?shell=glb` | `web/assets/console-b.glb`（Blender 导出） | **按导出的原样用**：材质/贴图/光照都不另加 |

两条路**共用**同一套：屏（离屏渲染的牌桌贴上去）、HTML 按键、键井、投影与浮层定位 ——
换掉的只有机身那一层。GLB 那条路页面只做两件功能上躲不开的事：屏换成离屏渲染的牌桌、
模型里当摆设的按键藏掉（能点的键由 HTML 覆盖层负责）。

一个容易误读的现象：GLB 的 `shellMat` 带着烘好的 AO，而那层 AO 里就含着**模型自己那几个键的
接触阴影**。展示页把模型的键藏掉了（改由 HTML 键接管点击），阴影还在，于是看起来像面板上的灰斑 ——
不是 UV 对不上，AO 本身没问题。想两全就把 HTML 键改成透明热区（见上）。

## 语言

- 座位名一律以**我方**为参照：我 / 上家 / 下家；位置也跟着以我方为参照 —— **我在最下**，两个对手在上。
- 地主、农民是**身份徽章**，不是座位名 —— 两者正交。
- 决策点对人一律叫**第 N 次出牌机会**；**全局手数**降级成小字（复盘时对齐记录用）。
- 粒子云的图例用 上家/下家，不再漏内部英文 id。

## 交互

- **镜头**：开场推镜；机身姿态由拖拽旋转、拖空白平移与滚轮缩放给，松手弹回默认姿态，不留可轨道旋转的相机。
- **录牌**：牌盘点选；轮到我方时，模型排好序的候选**点一下就记下这一手**。
- **牌盘的约束**：选牌不超过**牌池**里该点数的剩余张数；牌型与压制一律由服务端在提交时判（ADR-0001）。
- **牌盘的计数**：键面只写点数，张数做**右上角上标**，0 不显示。
- **窄屏**：保持 3D，固定正视、面板纵向堆叠；不维护第二套 2D 版式。

## 角色

三位角色用**扑克牌拟人**的像素精灵（花色元素 + 地主戴王冠），作公告板贴进 3D 场景。
先出 3 张站姿，构图定稿后再补"该他出牌"的动作帧。

## 分阶段

| 阶段 | 内容 |
|---|---|
| 1 | **快修（不依赖 3D）**：座位名改相对位置、决策点改"出牌机会"、牌盘加**牌池上限**、计数改上标 |
| 2 | 3D 机身 + 三位角色 + 三副牌 + 机顶记牌器 + 视差镜头（替掉现在的 2D 牌桌） |
| 3 | 机侧 CRT 面板：粒子云（补说明）+ 逐张概率 + 校准 |
| 4 | 操作台整合；可选：直接点 3D 桌上的牌来录 |

阶段 1 只改**将来会保留的 HTML 界面**（面板 / 操作台），且 3D 场景要用同一套词，所以不白做。

## 明确不做

- 不做可拖拽的轨道旋转（见上）。
- 不把斗地主规则搬进前端（ADR-0001）。
- 不在这一轮给角色做完整动画帧。
