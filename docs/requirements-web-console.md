# 展示页：模型壳子 + 平面覆盖层

## 目标

展示页以一台掌机为**唯一主界面**。机身来自 Blender 导出的 `web/assets/console-b.glb`（模型壳子）；牌桌画在机内真屏；座位牌、记牌条、操作台和数据面板是贴在机身周围/上方的 HTML 覆盖层。页面不是“3D 装饰 + 普通网页”，也不是可拖拽的模型展示器。

## 非目标

- 不做 3D 角色精灵；角色信息继续用 HTML 座位牌与身份徽章表达。
- 不做可拖拽轨道旋转；镜头只保留轻微鼠标视差。
- 不做 HTML 机身回退，不维护第二套程序化壳子。
- 不做玻璃反射、bloom、出牌飞行、推近镜头等表演性效果；这些是后续优化候选。
- 不做 GLB 压缩；本轮先保证几何、材质和加载链路正确。
- 不把文字、数字、控件画进 WebGL；文字始终是 HTML。

## 决策

### 3D 职责边界

three.js 只负责四件事：

1. 画模型壳子。
2. 把牌桌渲染进离屏 RenderTarget，再贴到模型 `Screen` 节点对应的真屏。
3. 把 3D 坐标投影成画布像素，供 HTML 覆盖层定位。
4. 在屏内做射线拾取，返回被点中的手牌。

机身尺寸、屏幕矩形和按键热区位置从 GLB **现量**；模型改了，页面跟着走。机身渲染以 `/glb` 为[保真](../../GLOSSARY.md)基准：只用基础灯，不开 IBL、不套 ACES；页面只额外加机底接触阴影。屏幕内容需要统一观感时，只调牌桌场景自己的灯与颜色（[ADR-0004](adr/0004-机身渲染对齐-glb-原貌.md)）。

### 页面结构

- 宽屏：机身居中偏左，数据面板作为机侧 HTML 副屏放在右侧。
- 窄屏：保留 3D 机身并固定正视；操作台、数据面板在机身下方纵向排列。
- 机顶：HTML 记牌条贴在模型顶部凹槽。
- 屏内：牌桌 + HTML 座位标签（我 / 上家 / 下家及身份徽章）。
- 机下：选牌结果、候选、开局录入和最小 44px 的触控操作条。
- 数据面板（粒子云、逐张概率、校准、页脚）默认收起；打开后在宽屏位于机侧，窄屏位于机下，**不得覆盖屏幕**。

### 模型按键与热区

- GLB 里的 `Buttons` 保持可见，是按键唯一外观来源。
- 可点性由透明 HTML 热区提供；热区不画键帽、不盖住模型图案。
- 热区从 `Buttons` 网格的连通块量出位置与尺寸，再投影到页面坐标。
- hover / focus 显示贴合键帽的描边；按下时描边下沉。模型键本身不位移。
- 窄屏仍在机下提供一条同功能、最小 44px 的 HTML 操作条，避免模型键缩得太小不可点。

### 状态与失败

- 没有 WebGL：机身区域显示明确提示，不加载第二套版式；依赖屏幕的操作禁用，数据面板仍可读。
- GLB 加载失败：机身区域显示错误原因和“重试”；不静默空白，不回退程序化壳子。
- 页面状态变化、尺寸变化、指针视差和动画只触发必要帧。
- 最后一次输入/动画结束后 500ms，新增渲染帧数为 0。
- 设备像素比上限 2。
- 暴露 `machineStatus()` 与 `frameStats()` 供浏览器验收读取。

## 保留 / 删除 / 重写

### 保留

- `web/app/api.js`、`state.js`、`labels.js` 的数据与命名职责。
- 牌桌、牌、离屏 RenderTarget、屏内射线拾取、3D→画布投影的实现思路。
- 操作台业务、开局录入、候选、撤销、终局收手等服务端交互。
- 记牌条、座位牌、粒子云、校准表的 HTML 内容。

### 删除

- `web/app/scene.js` 的程序化壳子：`buildConsole()`、`plate()`、`slabGeo()`、`slab()`、`roundedRect()`、`screw()`、`CHAMFER`。
- `?shell=glb` 开关与代码壳子回退。
- HTML 键帽外观和 3D 键井；按键外观交给 GLB，可点性交给透明热区。
- 旧“数据面板盖在屏幕上”的布局。

### 重写

- 新写职责更窄的 `web/app/machine.js`，承接模型加载、真屏、投影、拾取和按需渲染。
- `board.js` 改为消费 `machine.js` 的投影结果；删除 `setKeys()` 调用。
- `template.html` 调整主布局、机侧/机下面板、透明热区和窄屏操作条。
- `verify.mjs` 删除 `?shell=glb` 专用分支，增加模型壳子、热区、错误状态、保真像素基准与按需渲染验收。

## 验收

1. `node web/verify.mjs` 全绿；无 pageerror / console error。
2. 根路径直接使用 `console-b.glb`，不存在程序化壳子或 `?shell=glb` 分支。
3. `Shell / SideBand / Bezel / Screen / Trim / Buttons / KeyWell_L / KeyWell_R / Screws / SubDisplay / BackKey` 节点仍存在，`Buttons` 可见。
4. 屏幕矩形与手牌坐标来自模型；在 1280px 与 420px 视口都能点中真牌。
5. 模型键上覆盖透明热区：hover/focus 有描边，点击/键盘操作可用；模型键面图案不被 HTML 遮住。
6. 宽屏数据面板在机侧，窄屏在机下；任何视口都不覆盖屏幕。
7. 420px 下无横向溢出，机下操作条触控目标不小于 44px。
8. 无 WebGL 与 GLB 加载失败都有明确、可重试的错误状态，且不出现程序化壳子。
9. 静止 500ms 后 `frameStats()` 的新增帧数为 0；DPR 不超过 2。
10. 机身是[原貌渲染](../../GLOSSARY.md)（无 `scene.environment`、无 ACES、曝光/颜色空间与 `/glb` 一致）；`/glb` 仍按原样查看模型，保真像素检查（采样点与阈值见 `verify.mjs`）通过。

## 后续优化候选

按实际效果再决定，不进入本轮验收：

- 屏幕玻璃反射与屏幕内高光。
- bloom / 光晕。
- 出牌飞行动画。
- 推近镜头与镜头切换。
- 3D 角色精灵。
