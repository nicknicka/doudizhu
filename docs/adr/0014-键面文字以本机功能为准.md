# 键面的字以本机功能为准，形状与分件照三视图

机身按键的**字**写本机真实功能（推荐 / 撤销 / 出牌 / 不要），**不照抄**参考图的字样；
键面的**形状、位置、分件、材质**仍以 [三视图](../refs/console-3view/) 为准：黑菱形 + 阶梯描边 + 点阵字。
验收第 4 条按这条评 —— 形状 / 位置 / 材质对不上算不通过，**字面与参考图不一致不算**。

## Context

参考图（`docs/refs/console-3view/front-straight.jpg`）右握把那四颗菱形键写的是
**出牌 / 设置 / Pass / 提示**；本机这四颗的实际功能是：

| 位置 | 本机功能 | 参考图 |
| --- | --- | --- |
| 上 | 推荐（把模型排第一的候选选到桌上） | 出牌 |
| 左 | 撤销（撤掉刚记下的那一手） | 设置 |
| 右 | 出牌 | Pass |
| 下 | 不要（这一手不出） | 提示 |

**本机没有「设置」这个功能，却有「撤销」。** 独立评估连着两轮按第 4 条报 FAIL：形状、位置、质感都对上了，
只有字面与参考图不一致（原话：「四键：形状对，标签不对；缺『设置』，多『撤销』」）。

## Decision

- 键面的字 = 本机功能名。参考图的字样只作为「文字键 + 黑菱形 + 点阵」这套**语言**的依据，不是文案来源。
- 形状 / 位置 / 分件 / 材质照三视图；点阵字用仓库自带那份中文字体（`web/vendor/fusion-pixel-zh-hans.woff2`），
  与机顶 / 机下那层点阵字同一套笔画。
- 「撤销」不挪位、不改名；十字键中央那颗**灰标**保留 —— 它是"按得动"的提示（PR #69 定），
  改深色会丢掉这个提示。
- 机顶返回键的 **←** 属于形状语言（不是文案），照参考图补上。

## Considered Options

- **照参考图改字**（顶出牌 / 左设置 / 右 Pass / 底提示）：第 4 条能满分，但要给「设置」发明一个功能（本机没有这样的设置项），
  并把「撤销」挪到十字键上键。代价是机器上出现一颗语义靠凑的键 —— **按钮说谎比字面不齐更糟**。
- **把「撤销」改名成「设置」**：功能与字面直接矛盾，拒绝。
- **整颗键回退成图案**（★ / ↺ / ▶ / ✕）：正是评估两轮报的状态，语义更弱，方向反了。

## Consequences

- 以后评估照字面逐字比对按键时会给 FAIL —— 这是**已知且接受**的，不再当缺陷报。
- 参考图与常见掌机（A/B、Pass/提示）的用词差异不再触发改文案；要改的是**功能集**，那是产品决策，得单独开票。
- 键面文字从位图字形生成（见 `tools/console-blender/build_console.py` 的 `KEY_GLYPHS`）：Blender 端不装字库、
  不看系统中文字体，换台机器重建出来的字一模一样。
