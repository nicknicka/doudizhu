# 首屏加载层由标记承载，展示页只有一种形态

展示页刷新后的第一帧是一个信息极少的**加载层**，它由标记与样式直接给出，不等任何模块脚本执行；机身与首屏数据都就绪后，加载层退场、机身**入场**。展示页不再保留第二套"整页信息壳"形态。

## Context

首屏原本有两套形态：一套是标题 + 工具条 + 横幅 + 空机身的整页外壳，另一套是作为主角的极简舞台。切换它们的状态类由 `app/main.js` 添加，而该模块静态依赖整张模块图（含 three.js，753 KB）。ES 模块要等整张图下载并求值完才执行，所以外壳的消失时刻由网络速度决定：限速 4G 实测 7.1 秒、3G 实测 20.2 秒都在显示整页外壳。首帧可见性因此不能由模块脚本负责。

## Decision

- 加载层的状态类写在服务端渲染的标记里，不由脚本添加；它盖在整页之上，不参与布局，也不把机身画布设成不显示（画布容器的尺寸是相机与投影的输入）。
- 退场条件是机身与首屏数据**都**就绪，先就绪的一方不单独放行。
- 除模块脚本外，另有一小段不依赖模块图的传统脚本做硬兜底：超时或模块图失败时给出明确提示与重试入口，避免页面停在永远转动的加载层上。
- 展示页收敛成一种形态，旧整页外壳的标记与只服务于它的样式一并删除，四个操作入口由底部 dock 承担。

## Considered Options

- **由模块脚本添加状态类**：改动最小，但保留了 7 秒（限速 4G）以上的信息壳窗口 —— 拒绝。
- **保留整页外壳作为第二形态**：两套布局互为对照，代价是每个新功能都要在两处成立，且首屏到底露出哪一套由网络决定 —— 拒绝。
- **只靠 `<noscript>`**：覆盖不到"模块脚本下载失败"这种最常见的故障（脚本被禁用是一回事，脚本没下下来是另一回事）—— 拒绝。

## Consequences

- 首帧不再出现信息壳，但加载层的可见性从此由标记/样式与模块脚本两处共同决定：改首屏时必须同时想到那段传统兜底脚本。
- 加载层在完全不执行 JavaScript 的浏览器里仍然可见，因此它自带一句"需要 JavaScript"的提示，而不是一直转圈。
- 展示页只剩一种形态，"极简"失去对照对象，从代码与样式里退场。
