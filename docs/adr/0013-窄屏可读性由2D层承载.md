# 窄屏的可读性由 2D 层承载，3D 屏退成示意图

420px 视口下，**要读的数字与牌点由 2D 层承载**（机身下沿的常驻手牌条 + 机下/机侧数据面板）；
主屏纹理里的座位名、身份、张数只当**示意图**，不要求可读。**>620px 时相反**：屏内座位名与身份必须看得清，
因为它们承载「不悬停也知道谁是谁」这条要求（ADR-0008 的修订）。

## Context

验收标准第 7 条要求 420px 下机身**完整、不裁切**，第 3 / 6 条又要求「我那一手牌的点数能逐张分辨」、
「文字大到认得出点数」。这两条在 420px 下不可能同时成立，量一下就很清楚：

| 量 | 值 |
| --- | --- |
| 主屏 HUD 纹理 | 1536 × 804 |
| 420 视口下主屏的 CSS 宽度 | ≈209px |
| 换算 | 1 纹理 px ≈ 0.136 CSS px |
| 座位圆点半径 r | ≈24 纹理 px |
| 当前标签字号 0.72·r | ≈17 纹理 px ≈ **2.4 CSS px** |
| 要做到 10 CSS px | 字号 ≈73 纹理 px → 圆点直径 ≈200 纹理 px，占屏高约 1/4 |

机壳也加不大：`.machine` 的宽度已经是 `min(96vw, 1600px, calc((100vh - …) * 2.03))`，
420 视口下就是 ≈403px，主屏宽度被机壳比例锁死。**「整机不裁切」与「屏内贴图文字可读」是互斥的。**

## Decision

- 420px（`isTiny()`）下：主屏纹理里的字**按示意图对待**，不列入可读性判定；
  「我那一手牌的点数能逐张分辨」由机身下沿那条 2D 手牌条满足（13px 起，可点选）。
- \>620px 下：主屏纹理里的座位名 / 身份**必须可读** —— 它们是屏内唯一"谁是谁"的落点，
  且不随悬停才出现。为此给它们垫一块底色板（点阵字 + 硬边框，与记牌条同口径），
  否则墨色字落到深色桌皮上就糊了。
- 验收标准第 3 / 5 / 6 条按上面对应的层来评；第 5 条在 420px 下判「机身是主视觉、数据层贴在机身下沿」。

## Considered Options

- **推近镜头**：420px 下点数能到 ~11 CSS px；但桌上两家的牌堆被挤出画面，「一眼看懂」掉档，且与第 7 条冲突。
- **放大机壳超过视口**：屏内字号能上去；但机身被裁切，直接违反第 7 条。
- **撤销 2D 手牌条，只靠屏内**：就回到 6 CSS px 以下，第 3 / 6 条必挂。

## Consequences

- 窄屏只有**一套** 3D 版式（机身照常整体可见），可读性靠 2D 层，不额外维护第二套 3D 版式 —— 与 ADR-0002 同一条思路。
- 主屏贴图里的文字在 420px 下会糊，这是**已知且接受**的，不再当缺陷报。
- 修订 ADR-0008：座位名 / 身份不再只留在 DOM 悬停卡片里，也画进主屏纹理（那里才跟机身一起转）；代价是它们在贴图里会随缩放变软。
