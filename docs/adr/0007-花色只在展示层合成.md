# 花色只在展示层合成

牌局记录继续只保存点数，展示页在渲染时按 `record_id` 和点数确定性地给每个点数的四张牌合成 ♠♥♦♣，并让同一张虚拟牌在手牌与出牌区之间保持身份一致。斗地主规则不区分花色，记录里也没有花色；把花色写回记录只会为展示信息增加 schema 与迁移成本，并制造第二个事实来源。规则合法性仍由服务端裁定（[ADR-0001](0001-合法性由服务端裁定.md)）。

## Considered Options

- **给记录里的牌增加花色或牌 ID**：能让花色的来源更直白，但要改 schema、录制格式和所有消费方，且表达的仍然是规则不需要、真值里也不存在的信息 —— 拒绝。
- **每次重绘随机分配花色**：实现短暂，但复看时同一张牌会换花色，也无法保证整局不重复 —— 拒绝。

## Consequences

- 展示层必须维护一局内的虚拟牌身份，并保证 54 张牌的（点数、花色）组合不重复。
- 花色不是可导出的牌局事实；导出的记录仍然只有点数。
