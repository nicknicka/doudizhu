# 牌局合法性的唯一裁判是服务端

页面**不实现斗地主规则**。它能施加的约束只有一条：选牌不超过**牌池**里该点数的剩余张数 —— 而"牌池"由后端推好发下来。牌型是否成立、压不压得住上一手，一律由服务端在提交时判定并给出可读理由。

规则一旦在前后端各写一份，两份必然漂移，而且漂移会以"页面放行了非法出牌"这种最难发现的形式暴露。页面少一次即时校验，换来的是规则永远只有一个来源。

## Considered Options

- **前端也实现一遍牌型与压制判定**：能有即时反馈，但要维护两份斗地主规则 —— 拒绝。
- **服务端把当前所有可能出的牌算好发下来，前端只允许从中选**：对我方已经这么做（候选一键录）；对**对手**做不到 —— 我们本来就不知道他们手上有什么，只能退回"不超过牌池张数"这条可靠约束。
