# 机身渲染对齐 `/glb` 原貌，不套页面级后处理

展示页的[模型壳子](../../GLOSSARY.md)以 `/glb` 的单模型渲染为[保真](../../GLOSSARY.md)基准：沿用它的三盏基础灯（Ambient 1.2 / key 1.6 / fill 0.5），不开 `scene.environment`，不设 ACES 等色调映射，输出颜色空间与 `/glb` 一致。页面只加能明确说明理由、且不改写模型材质响应的层；本轮唯一允许的额外层是机底接触阴影。模型自己已经把米色壳、靛蓝侧带、金色描边和键帽材质做完了，页面的 IBL + ACES 只会把米色顶白、金线漂白、深描边提起；需要屏幕内容与机身统一观感时，调牌桌场景自己的灯与颜色，不回头给整台机子套统调。

## Considered Options

- **保留 IBL + ACES，只降低强度**：观感最容易与屏幕内容统一，但调亮的路径仍在 —— 之后每次“再亮一点/再高级一点”都会继续磨掉模型原貌；拒绝。
- **机身单独走原貌渲染，屏幕与覆盖层另做统调**：界线清楚，但多一套颜色管线；当前页面复杂度不值得，拒绝。
- **完全不处理**：最省事，但机器会像悬在背景上；允许且只允许机底接触阴影作为这一层例外。

## Consequences

- `machineStatus()` 必须暴露环境贴图、色调映射、曝光与三盏灯的参数，浏览器验收可以直接断言，不靠肉眼判断。
- 屏幕内容与机身共用同一个 renderer。`NoToneMapping` 后牌桌若显得太生，只调 `tableScene` 的灯和颜色，不能加回全局后处理。
- `/glb` 从“参考页”升级为硬基准；要改它的渲染配置，必须同时改本 ADR。
- 模型几何本轮冻结；模型本身的改动另走 build 脚本与独立审查流程。
