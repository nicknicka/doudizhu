# three.js 只负责机身、真屏与拾取，文字与控件留 HTML

展示页的机身**只有一个来源**：Blender 导出的 `web/assets/console-b.glb`（[模型壳子](../../GLOSSARY.md)）。页面里由 three.js 现算机身的**程序化壳子**整块删除，`?shell=glb` 开关一并删掉 —— 它存在的唯一理由就是给旧壳子留后路。

three.js 的职责因此收窄成四条：① 画机身；② 把牌桌渲染进离屏 RenderTarget 再贴到屏上（屏是**真屏**）；③ 把 3D 坐标投影成画布像素，供 HTML [覆盖层](../../GLOSSARY.md)定位；④ 屏内的射线拾取（点牌）。文字与数字、以及所有可点控件仍是平面 HTML（理由见 [ADR-0002](0002-机身用3D-文字面板留2D.md)）；按键的**外观**由模型给，**可点性**由盖在上面的透明[热区](../../GLOSSARY.md)给。

## Considered Options

- **不用 three.js**：机身用预渲染图（正/3‑4 各一张）+ HTML 面板。本机服务下省下的体积换不到体验，却要放弃视差、屏幕反光与镜头表演，而且以后想改姿态就得重新出图。
- **两条壳子并存（程序化壳子做回退）**：观感、尺寸、材质各维护一套，等于长期维护两台机器。

## Consequences

- 机身尺寸、屏幕位置、按键位置都从 GLB **现量**（玻璃节点的包围盒等），不再由页面常量决定；模型改了页面跟着走。
- 渲染改为**按需**：静止不动时不画帧；设备像素比上限 2。
- 没有 WebGL 时不维护第二套版式，只给一句提示。
- 角色精灵、机侧数据面板、窄屏版式**不受本决定约束**，各自单独定。
