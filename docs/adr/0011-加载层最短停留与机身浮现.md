# 加载层最短停留，收尾播完才让机身浮现

加载层不再"一就绪就走"：它至少停 **900ms**，收尾动画（收成一条线，260ms）**播完才摘幕布**，机身的入场（淡入 + 从 0.94 缩放回 1）等在幕布收完之后才开始。

## Context

ADR-0009 把首屏可见性交给标记，等机身与首屏数据都就绪再退场。实践里暴露两个手感问题：

1. **机身快的时候像闪屏**：就绪即退场，幕布只露一两百毫秒就走，读起来不是"开机"而是"闪了一下"。
2. **机身是在幕布后面偷偷播完的**：入场动画（0.8s 缩放）在模型装载的那一刻就开跑，等幕布收完时它早播完了 —— 露出来的是一台**已经站定**的机器，没有"登场"。
3. 退场那次摘类用的是固定 `setTimeout(260)`：定时器和 CSS 动画各算各的，遇上主线程忙（装载后正是最忙的时候）就会把最后一帧切掉。

## Decision

- **最短停留 900ms**（`window.__bootDwellMs`）：从 HTML 解析起算，机身再快也让这一拍走完。交接请求来得早不早都不影响这一拍。
- **收尾播完才摘幕布**：退场用 `animationend`（只认 `bootFoldOff`）驱动摘类；另留 800ms 兜底，动画没起来也不会把页面锁在幕布里；`prefers-reduced-motion` 下跳过停留与退场动画，直接收口。
- **机身浮现等幕布**：模型就绪时先落到入场起点（`rig.scale = 0.94`、画布 `opacity: 0`）但不播；加载层摘类的同一个动作里派发 `boot:done`，`machine.js` 听到它才开始"淡入 + 缩放回 1"。没有幕布可等时（例如 8s 强放行之后才就绪）立即播，不改变那种路径。
- 时间轴留在 `window.__bootAt = { shown, exitStart, done }`，`machineStatus()` 补 `entranceStartedAt` —— 验收据此判断，不靠人眼。

## Considered Options

- **只在就绪后延迟固定毫秒**：实现最省，但"机身多慢就多等"没变，慢网下幕布更久 —— 用最长的那一头去补最短的那一头，方向不对。
- **加载层淡出（opacity）**：淡出期间机身已经在后面，等于两块内容叠着过渡，容易糊 —— 选"收成一条线"再浮现。
- **给机身做材质级淡入**：要逐个改 mesh 的 `transparent/opacity`，会和 ADR-0006 的投影、以及保真比色互相干扰 —— 改成淡画布（`#scene` 的 CSS opacity）+ 缩放，三维那边的可见性一行没动。

## Consequences

- 首次进入的下限变成约 **1.16s**（900ms 停留 + 260ms 收尾）；机身慢的时候总时长照旧由它决定。
- "就绪"与"露出"从此是两件事：机身先装好、在幕布后面**不动**，收到 `boot:done` 才登场。
- 验收多了三条硬断言（verify）：最短停留 ≥ 840ms、收尾落在 180–600ms（既不能立即摘、也不能靠兜底）、入场时间戳不早于幕布摘掉。
