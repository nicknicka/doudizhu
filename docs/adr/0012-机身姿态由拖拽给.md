# 机身姿态由拖拽与平移给，取消鼠标视差

机身不再跟着鼠标漂。姿态只由用户的**拖拽旋转**、**拖空白平移**、**滚轮缩放**与**按键冲量**决定；鼠标只是移到哪里，不再改变机身。松手后弹回默认姿态，不留一个可轨道旋转的相机。

## Context

ADR-0002 定下的镜头行为是「跟随鼠标的轻微视差，不做可拖拽的轨道旋转」。后来机身改成可拖拽：`dragYaw` / `dragTilt` 给旋转，`panX` / `panY` 给平移，滚轮给缩放，按键给冲量。视差此时没有位置可站 —— 它和拖动弹簧写同一份姿态（`rig.position` 与 `rig.rotation`），被当时的注释记为「拖动中抖动的主因」。中间的补丁是拖动期间冻结视差、松手再恢复，等于让两套动画轮流停摆。

视差在 `prefers-reduced-motion` 下本来就整段关掉，所以它在「关掉动效」的场合也不携带信息。

## Decision

- 删掉 `capParallax()` / `animateParallax()` 与 `pointerTarget` / `view` / `parallax*` 这一组状态。
- `applyRigPose()` 只写 `panX` / `panY` / `dragYaw` / `dragTilt` / `rigZoom` / `pressKick`。
- 鼠标停在机身上不再产生渲染帧；姿态变化只由输入事件与弹簧收敛驱动。

## Considered Options

- **保留视差，拖动期间冻结**：这是当时的做法。两套弹簧轮流停摆，恢复时机还要在 `endDrag()` / `endPan()` 里手工接上，抖动只是被推迟到松手那一刻 —— 拒绝。
- **把视差挪到相机**：可以避开姿态争用，但机身已经有拖拽旋转这套更直接的姿态控制，再叠一层相机漂移会让人分不清自己在拖什么 —— 拒绝。
- **保留视差，把幅度降到几乎看不见**：等于留着一段没有可读效果的动画，还继续占 `relayout()` 的帧预算 —— 拒绝。

## Consequences

- 姿态只有一条写入路径，拖动中不再需要「冻结 / 恢复」这套时序。
- 部分取代 ADR-0002「镜头只做跟随鼠标的轻微视差，不做可拖拽的轨道旋转」这一条：**两个半句都反了**。其余部分（机身与牌桌 3D、数据面板留 2D）继续有效。
- 「指针视差只触发必要帧」这类验收口径跟着失效：鼠标悬停不再出帧，静止判据更容易成立。
