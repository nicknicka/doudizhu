# 展示页的视觉验收怎么评

展示页的改动，尤其是 3D 与视觉相关的，按这份流程评。评的是**看得到的作品**（截图），不是作者的理由。

## 7 条验收标准

| # | 标准 |
|---|---|
| 1 | **像一台机器**：机身/屏幕/握把/机顶/机侧在视觉上是一件整体，不是「3D 装饰 + 普通网页」 |
| 2 | **一眼看懂**：没看过这项目的人，能说出「三个人的牌桌，我在下面，两个对手在上面」 |
| 3 | **可读性**：张数、已出牌、身份徽章、出牌机会编号都看得清；**我那一手牌的点数能逐张分辨**。420px 下这一条由 2D 层承载（[ADR-0013](../adr/0013-窄屏可读性由2D层承载.md)） |
| 4 | **造型与质感按三视图**（[`refs/console-3view/`](../refs/console-3view/)）：剪影、比例、分件、按键以图为准；**允许**倒角高光、AO、环境光渐变与柔影。信息层（记牌条、座位牌、操作台）仍保持点阵字、硬边框、限色。按键的**字**以本机功能为准（[ADR-0014](../adr/0014-键面文字以本机功能为准.md)）—— 形状 / 位置 / 材质照图，字面不照抄 |
| 5 | **层级清楚**：牌桌是主视觉，数据面板是配角，不抢。420px 下判「机身是主视觉、2D 数据层贴在机身下沿」 |
| 6 | **不糊**：中文与数字清晰；3D 场景里的文字大到认得出点数。**420px 下屏内贴图文字不列入判定**（[ADR-0013](../adr/0013-窄屏可读性由2D层承载.md)） |
| 7 | **窄屏不崩**：420px 下仍然是一台机器，没有重叠或裁切 |

### 第 4 条的适用范围

第 4 条评的是**机身**与三视图的一致性，它跟着机身那条线走（#17 / #24）。
只改牌面、数据层、交互的改动，第 4 条按**「没有回退」**评 —— 不借一次牌面改动重新审一遍机件语义。

功能与结构上的验收（`web/verify.mjs` 全绿、模型节点仍在、坐标点得中……）见
[`requirements-web-console.md`](../requirements-web-console.md)「验收」，那是另一把尺。

## 流程

1. 改完之后**派一个独立的 sub-agent 去评估**，**不许作者自评**。
2. 评估给出 PASS/FAIL + 证据；不过关就按它给的优先级继续改，**再派一个新的评估 agent**。
3. **只有评估过关，才通知用户**（中间不要打扰）。
4. 交给评估 agent 的输入**只有作品（截图）+ 上面这 7 条**，不给作者的理由；要求它**逐条 PASS/FAIL + 证据 + 最差项 + 三条优先修复**，并明确要求它挑刺、不留情面。

## 独立性要如实交代

评估 agent 与作者用同款模型时，独立性是打折的 —— 每次都要主动向用户声明，不要把它说成异构评审。能换一款模型就用异款。
