# 阶段计划与验收标准

> **实时状态不在这份文档里**：工作项、依赖关系与完成情况以 [Issues](https://github.com/nicknicka/doudizhu/issues) 为准。这里保留的是阶段划分与验收标准的定义。

每个阶段都以**外人可验证**的产物结束，而不是"我觉得差不多了"。

## S0 — 环境与规则核对

| 任务 | 说明 |
|---|---|
| 建 venv | 锁定 `numpy==1.26.4`（保守选择，见 [environment.md](environment.md)） |
| 装依赖 | `rlcard` + `onnxruntime`，**不装 PyTorch** |
| 下载权重 | DouZero-WP 三个 ONNX，约 18 MB |
| 跑通一局 | RLCard 自对弈一局，确认能取到全部玩家真实手牌 |
| 规则比对 | 拿一局真实牌局逐条核对下面四条 |

**验收**：环境可被他人按文档复现；四条规则比对无差异。

四条必须核对的规则差异点：

1. 顺子最少 5 张
2. 连对最少 3 对
3. 飞机带翅膀的张数规定
4. 炸弹与火箭的压制关系

## S1 — CLI 与记录层

| 任务 | 说明 |
|---|---|
| `record/` | Schema 定义 + `save` / `load` / `replay` |
| round-trip 测试 | `load(save(x)) == x` 且可回放 |
| `source/manual.py` | 手动结构化录入一个局面 |
| `policy/douzero.py` | 加载 ONNX，输出合法动作分数 |
| `cli/` | 给定局面 → 3 个候选动作 + 胜率估计 |

**验收**：同一局面重跑结果一致；round-trip 测试通过。

## S2 — 手牌推断与评测

| 任务 | 说明 |
|---|---|
| `inference/` | 约束过滤 + 粒子采样，输出另两家手牌分布 |
| `source/sim.py` | 自对弈批量生成带真值的局面 |
| `evaluation/` | Top-k 命中率、真值对数似然、校准摘要 |
| 基线对照 | 与均匀随机采样对比 |

**验收**：在 N 局上产出可复现的命中率数字；N 与全部参数写进 README。

## S3 — 作品化

| 任务 | 说明 |
|---|---|
| Web | 局面展示、候选胜率、手牌热力图 |
| 录屏 | 2 分钟演示 |
| README | 补齐运行说明、评测结果、架构说明 |

**验收**：外人看完录屏能说清"做了什么、难在哪"。

## 时间不够时的砍伐顺序

**UI → 真实对局录入 → 校准 → 推断主线**

推断主线放最后：砍掉它，项目就从"有领域深度的决策服务"退化成"模型套壳"，不如换项目。

## 已知风险

| 风险 | 对策 |
|---|---|
| ~~numpy 2.x 兼容性~~ **已推翻** | 实测 numpy 2.4.6 下 RLCard 可跑通；保留 1.x 锁只为锁定已验证配置 |
| 磁盘空间紧张 | pip 加 `--no-cache-dir`；走 ONNX 路线避开 PyTorch |
| 实际平台规则与 RLCard 实现有差异 | S0 逐条比对，不一致必须重新评估 |
| 模型输出是 Q 值，不等于校准胜率 | 对外措辞准确：只说"模型给出的估计" |
| 不完美信息下的质量上限 | 用随机基线对照，陈述"比瞎猜强多少" |
